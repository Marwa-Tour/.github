# Централизация GitHub

Публичный репозиторий `Marwa-Tour/.github` хранит профиль и общие настройки организации. Перед изменением видимости история была проверена на секреты, токены и приватные ключи; совпадений не найдено.

## Что находится здесь

- `.github/workflows/validate-branch-and-commits.yml` — reusable workflow проверки веток и commits.
- `.github/pull_request_template.md` — шаблон для новых репозиториев без собственного шаблона.
- `.github/CODEOWNERS` — владельцы этого репозитория.
- `.githooks/commit-msg` — локальная проверка commits этого репозитория.
- `profile/README.md` — публичная стартовая страница организации.

Reusable workflow доступен private repositories организации. В файлах `.github` нельзя хранить secrets: они задаются только через GitHub Actions Secrets.

## Защита main

После публикации репозитория бесплатная branch protection включена для `main`:

- изменения только через pull request;
- минимум один approval и обязательный review CODEOWNERS;
- после нового push прежние approvals сбрасываются;
- последний push подтверждает другой участник;
- обязателен успешный `validate / Validate branch and commits`;
- все обсуждения должны быть закрыты;
- ветка должна быть актуальна относительно `main`;
- запрещены force-push и удаление `main`;
- правила применяются к администраторам;
- разрешена только линейная история и `Squash and merge`.

Первый bootstrap-коммит создал `main` и reusable workflow: пустой репозиторий без базовой ветки не позволяет открыть pull request, а вызывающие репозитории должны ссылаться на существующий `@main`. Все дальнейшие изменения общей конфигурации выполняются через отдельную ветку и pull request.

## Подключение репозитория

В вызывающем репозитории нужен файл `.github/workflows/validate-git-conventions.yml`:

```yaml
name: Validate branch and commits

on:
  pull_request:
    branches: [main]

permissions:
  contents: read

jobs:
  validate:
    uses: Marwa-Tour/.github/.github/workflows/validate-branch-and-commits.yml@main
```

Маленький вызывающий файл обязателен: GitHub не запускает workflow другого репозитория автоматически.

## Что остаётся локально

- `CODEOWNERS`, если владельцы конкретного кода отличаются.
- `commit-msg` hook и установщик: Git запускает hooks с компьютера разработчика.
- PR template может оставаться локальным и имеет приоритет над общим.

## Изменение правил

Сначала измените и проверьте reusable workflow здесь. После merge в `main` изменения начнут использовать все подключённые репозитории. Не переименовывайте файл без одновременного обновления вызывающих workflows.
